# 日用品コスパ比較｜検索表示減少の原因を日別・ページ別に切り分ける

## 調査を始める根拠（2026年10月10日・実測）

Google Search Console（対象URLプレフィックスは https://stusaurus.github.io/daily-cost-jp/ ）の2026年9月24〜30日と10月1〜7日を比べたところ：

| ページ | 9/24〜9/30 | 10/1〜10/7 | 増減 |
|---|---:|---:|---:|
| サイト全体 | 36回 | 8回 | -28回 |
| ティッシュ | 30回 | 1回 | -29回 |
| 洗濯洗剤 | 3回 | 4回 | +1回 |
| トイレットペーパー | 1回 | 2回 | +1回 |

**サイト全体の減少は主にティッシュページの検索表示の変化による。** ただし、特に後半週は表示8回しかなく、検索順位の急落、ペナルティ、検索需要の消失、インデックス不具合を断定する根拠はない。

実際の公開サイトは2026年10月10日にPC・スマホで確認済み。SEOタイトル・description・canonical・robots/noindexの設定に明確な不具合は見つからなかった。

## 追加する自動調査

既存の3日ごと分析のSearch Console取得直後に、同じ読み取り専用認証で**直近28日分の日別サイト表示と、日別ページ表示**を取得する。

- Search Analytics APIで日付、日付＋ページの2種類を問い合わせる。
- 結果保存はサイト全体＋主要3カテゴリの**日別合計のみ**。検索語・個人に結び付く情報は記録しない。
- 日別行が返らない日は「不明」。絶対に0を埋めない。
- 日別集計が28日集計と合わない場合は、その日別表を使って原因を断定せず「集計不整合」と記録する。
- 週別の数字は既存のGSC実績を流用し、特定ページに大きな変化があるかを表示。
- GSCの日別追加取得に失敗しても、従来のGA4・GSC統合報告・PC/スマホ自動監査を継続する。
- LOW_SAMPLE は計測数が少なく推測に注意が必要という意味で、「順位が下がった」ことを意味しない。

## これでも分からないこと

日別の集計だけでは、「なぜ検索で表示されなくなったか」は確定できない。検索語の明細はプライバシー配慮によって公開レポートから除外されることがあり、Search Consoleの順位も表示回数で重み付けされた平均である。検索順位の変化・需要減少・インデックス・競合を断定しない。

十分な裏付けなしに現在のSEOタイトルや説明文を変更しない。商品情報・容量比較・送料判定・楽天アフィリエイトID・購入リンク・Search Consoleプロパティ・サイトマップ・公開済みページは一切変更しない。

## 確認先

GitHub stusaurus/daily-cost-jp → Actions → GA4 Three-Day Read-Only Analysis → 実行のSummary → 「Google検索表示の減少｜日別・ページ別調査」。

30日保存の ga4-three-day-report 成果物に gsc-daily-search-change.json と .md を追加する。初回本番実行で、直近28日のSearch Console日別API取得に成功したかを確認するまでは、新しい日別集計を実稼働確認済みとは表現しない。

## 次の行動判断

- 変化が一日だけの偏りなら、順位低下とは判断せず継続監視。
- ティッシュだけ低調な日が継続するなら、Search Consoleで個別検索語・デバイス・インデックス状況を確認する。
- 技術的な問題が実画面で再現したときだけ、別PRで最小限の修正を行いテスト・レビューする。
- 十分な検索語の根拠が揃った場合のみSEOタイトルや見出しの改善案を検討し、効果を長期間比較する。
