# GA4改善候補→PC・スマホ実画面QA（読み取り専用）

## 目的
3日ごとのGA4分析が「調査候補」と判定したページを、実際の公開サイトのPC／スマホ表示で検査する。**売上に寄与したかどうかの判定や、自動修正・自動公開は行わない。**

## 検査
- GA4の集計結果から高優先度のページを最大2つ追加し、固定の重要3カテゴリ（洗濯洗剤・ティッシュ・トイレットペーパー）と合わせて最大5ページを点検。
- 画面幅 1440px、390px、320px で実際にGitHub Pagesを開き、スクリーンショットを残す。
- HTTP 200、主見出し、横スクロール、カテゴリの価格比較欄、楽天購入ボタンの存在・可視性・URL形式・タップ領域を判定。
- ページのJavaScript例外を記録。警告と重大エラーを区別。
- GA4で「閲覧数が少ない」とされたページの表示状態も点検するが、「サイト不具合」と「検索流入の不足」は別の問題として扱う。

## 厳格な安全制限
- 診断はブラウザの表示・DOM検査だけで完結。クリック・購入・外部リンク遷移は**一切行わない**。
- Google Analytics／Google Tag Managerへの通信を遮断し、ブラウザには運営者テストフラグを付与。GA4の数値を人工的に増やさない。
- 楽天リンクのURLの構文のみ確認。**楽天への接続やリダイレクト検証をしない**ため、URLが実際に購入成功へつながることまでは保証しない。
- GA4候補をそのまま任意URLとして開かない。検証対象はサイト内のカテゴリ、トップ、商品検索、今日のお得のパスに限定。
- GitHub Actionsのbrowser-qaジョブはcontents: readのみ。サイトの書き換え・push・deploy・Secretsへのアクセスは実施しない。
- 「FAIL」はブラウザ上の技術的異常のため調査を優先。「REVIEW」は小さなボタンや横はみ出しなど、手動確認が必要な警告。
- ジョブが失敗しても、可能な範囲でスクリーンショットと集計結果を保存する。

## 実行場所
- PR作成時：GA4 Three-Day Read-Only Analysis の Verify new browser QA against production (PR only) が重要3カテゴリを匿名ブラウザで検証。
- 本番反映後：3日間GA4取得ジョブが成功したとき、続く Read-only production browser CTA audit が同じ実行のGA4候補ファイルを取得してPC／スマホ検証。
- GitHubの Actions → GA4 Three-Day Read-Only Analysis → Summary の日本語表を確認。
- 画像・JSON・Markdownは ga4-live-cta-qa 成果物として14日間保存。

## 今後の段階（未実装）
1. 現実の不具合が再現する場合のみ独立の改善PRを提案。
2. 商品・単価・送料・楽天リンク・アフィリエイトタグ・GA4計測の変更は自動修正対象外。
3. GitHubの既存QAと差分回帰テスト、モバイルスクリーンショット、ロールバック設計を満たしたときだけ手動承認を求める。
4. 自動公開は別途安全性と効果が確認されるまで有効化しない。
