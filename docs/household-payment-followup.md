# 数量別候補の条件付き追加検索

## 問題と検証条件

既存取得は、各数量帯の最初の固定検索で有効な候補が見つかると次の検索を省略する。10月19日の診断では、洗剤少量380gが2,552円・普段用1,590gが1,561円、ティッシュ普段用20箱が6,952円・まとめ買い60箱が5,299円だった。異なるブランド・仕様であり同一商品の価格差や節約額ではないが、買いやすい支払総額の候補を取り逃していないか検証する必要がある。

## 変更範囲

- PR #111の支払総額診断を既存数量別選定モジュールへ共通化。診断結果・同一商品未確認という意味は維持する。
- 最初の取得は既存通り早期終了する。検証済み選定枠に支払総額の逆転がある数量帯だけ、未使用の既存固定検索を1回試す。新キーワードやページ巡回を追加せず、カテゴリごと最大4リクエスト・候補30件を維持する。正常な数量帯のリクエストは増やさない。
- 数量・送料・商品ID・用途・比較単位・全体外れ値の既存判定を再適用。該当数量帯の支払総額が下がり、他の選定枠が完全に同じ場合だけ追加結果を採用する。比較単位が違う・他の枠が欠ける・価格改善なし・失敗の場合は元候補を保持する。
- 単価ランキングは変更しない。ブランド一致・同一SKU・1回使用当たりコストや成果報酬の改善は主張しない。新しい推薦器・PR生成器・監視workflowは作らない。
- 商品取得/選定モジュールの修正を既存公開workflowの対象パスに含める。定期更新とX投稿条件は維持する。

## 公開前の実測比較

既存STEP5の未公開検証で、新処理が取得した応答をメモリ内で保持し、旧早期終了処理へ再入力する。旧処理用の追加API呼び出しは0。公開artifactには匿名参照・数量・金額・比較単位・リクエスト数・改善した枠だけを保存し、生の応答や認証情報を保存しない。

マージ前に、この実測比較で支払条件の改善があることと、既存ランキング・商品リンク・PC/スマホ・品質ゲートの維持を確認する。改善が確認できなければ本番採用を見送る。購入率・売上・検索順位の効果はこの比較では検証できない。
