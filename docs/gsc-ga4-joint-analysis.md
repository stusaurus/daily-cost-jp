# 日用品サイト｜GSC × GA4 統合調査（3日周期・読み取り専用）

## 何を自動化するか

既存の「GA4 3日間のクリック分析 → 7/28日ページ別診断 → ChromiumでPC/390px/320px実画面確認」に、**すでに接続済みのSearch Console**からの検索表示数・検索クリック・平均掲載順位を加える。

1. 3日ごとにmain限定GitHub Actionsが起動。既存のWIFサービスアカウントを使う。
2. GA4から本番サイトページの表示数と「楽天クリック（operator_test=1 / 0 / 不明）」を取得。
3. Search Consoleから同じ日用品URLプレフィックスの検索表示・クリック・平均掲載順位を取得。
4. 「検索結果で見られているのにクリックされない」「検索流入はあるが楽天リンクまで進む理由が不明」「クリックにテスト区分不明がある」などの**調査仮説**をページごとに選別。
5. 日本語の表をGitHub Actions Summaryと30日保存の成果物に出力。
6. 固定3カテゴリ＋優先調査ページ（最大2ページ）をPC・390px・320pxの実ブラウザで読む。GA4や楽天へ外部クリックしない。

## 断定してはいけないこと

**検索クリック・GA4閲覧・楽天クリックは別の指標。** 同じユーザーが行動したことを確認できないので「Google検索から購入した割合」などの成約率は算出しない。楽天アフィリエイトの確定報酬にも接続していない。

今回のGoogleデータで扱う28日間は以下のように**1日異なる**。

- GSC: 実行日の3日前までの28日間
- GA4: 実行日の2日前までの28日間

そのため、両者の数字を割ってコンバージョン率にしない。Search Consoleのページ行がない場合も、検索0件を意味するとは限らない。

運営者テスト以外のクリックを表示する場合も、明確な operator_test=0 だけを暫定値として扱う。operator_testが未登録または区分不明なら、推測で一般ユーザーのクリックとはみなさない。

## 失敗時と既存機能の保護

- **GSCがアクセス拒否・通信不能でも、GA4分析とブラウザ監査は続行する。**
- GSC失敗・未接続を0回とみなさず、統合状態 GSC_UNAVAILABLE としてレポートを保存。
- GSCプロパティは https://stusaurus.github.io/daily-cost-jp/ 完全一致。
- ワークフローはGA4・GSCの読み取り専用スコープを使い、main限定OIDC認証。PRではGoogle認証を使わずテストのみ。
- 無許可URLへのブラウザアクセスは禁止。調査候補は決められたサイトパスから最大2ページ選択。
- GitHub書き込み権限、商品の再検索・価格変更・楽天タグ変更・SEO文章の自動修正・自動公開は追加していない。

## 次に行う検証

1. 新しい統合分析の単体テストと既存の全サイトQAの完了を確認。
2. PRをmainへ反映し、初回の本番レポートで Search Console=PROVISIONAL と統合状態 JOINT_PROVISIONAL を確認。
3. 生データの意味が正しいか、洗濯洗剤・ティッシュ・トイレットペーパーの検索とGA4を照合。
4. 調査仮説に応じて、**別途**安全な改善案を作る。公開の自動判断はまだ許可しない。
