# STEP10 計測の監査（2026-10-20）

旧live_purchase_qa.cjsはtest=1を付けてもGA4の通信を遮断せず、カテゴリー/アリエール/スコッティの3経路で楽天購入リンクを開いていた。公開後Lighthouseにも通信遮断がなかった。テスト区分の存在と、送信自体の防止は別である。過去の楽天レポートを一律テスト由来と断定できず、GA4と同一人物として結合しない。

既存STEP3のリクエストallowlistを旧QAの全BrowserContextへ設定。Service Workerを無効化し、サイト/商品画像/既存読み取り専用Worker API以外を遮断する。楽天リンクはURL検証だけとしクリック/外部遷移を除去。Workerは実応答、商品選定・通常閲覧の計測コードは変更しない。公開/未公開LighthouseにもGA/広告/アフィリエイト転送の遮断を設定する。

既存GA4分析のtraffic_evidenceはoperator_test=1の確認済みテスト、0のテストの可能性を含む未検証利用、欠落の出所不明を保持する。正当利用の根拠はUNKNOWN/count=null。0を実顧客と断定しない。既存カウント/期間/判定閾値と、未知/未接続の状態は維持。セッションやページ表示にはテスト/未知が含まれ、人間の人数ではない。

一般の本番ユーザーは従来のpage_viewとaffiliate_clickを記録する。GA4以外の拡張計測clickやproduct_result_clickは異なるイベントで、合算して購入者数にしない。既存のJSDOM計測テストで通常/テスト/不明、クリックの重複防止を回帰検証する。Workの手動閲覧はtest=1のON表示を確認し楽天をクリックしない。ブラウザー側で通信遮断を設定できない手動閲覧は、本番GA4へ確認済みテストとして送信され得る。未標識の本人操作は分類不能。

楽天のクリックはブラウザー設定/ブロッカー/別端末/計測方式がGA4と異なる。レポートの期間/タイムゾーン/定義を揃えず差を追跡漏れや同一ユーザーとして扱わない。楽天の確定成果は既存STEP7に未接続で、公開リポジトリへ報酬/個人情報を追加しない。
