# STEP 4-C：検索原因と購入導線計測

依存：B（PR #81）→C。既存の価格・マッチャー・API順序・リンクは変更しない。原因はAPI失敗、API0件、数量解析失敗/可変、送料不明、商品不一致、危険候補、価格付き安全候補0件へ分ける。取得10件・価格0件は商品なしではない。原因がAPIに含まれないものはUNRESOLVED。推測で送料不明や数量失敗と決めつけない。追加確認中はPENDING。初期・最終各1イベント、世代IDで古い検索結果の混入を防ぐ。

新規`purchase_search_diagnostics`は状況コード、初期/最終、件数と原因別集計だけ。検索語・商品名・ID・URLは送らない。新イベントのpage_locationはクエリを除く。既存GA4イベントを保持し、既存affiliate_clickに3値のpurchase_purposeだけを追加。保存/比較にはpurchase_saved_open、purchase_comparison_open、purchase_save_add、purchase_compare_addを各操作1件で記録。operator_test、site_id、traffic_environmentは既存wrapper。実購入や外部クリックをテストに使わない。

28日集計は既存Google read-only権限を使用。新規APIキー不要。eventName/date/pageLocation/operator_testだけを取得して固定ページと固定イベントへ集約し、生レスポンス・生検索語を保存しない。レスポンス切り捨て・thresholdingは失敗とし0扱いしない。operator不明・運営者は一般利用者から除外。page_viewで観測された日数は計測正常日数の証明ではない。欠測か0訪問か不明とする。既存pageview集計には運営者を含むため比率の分母として使わない。

原因別GA4レポートと目的別クリックの細分化はカスタムディメンション未照会。匿名理由内訳はブラウザ内の診断とQAで検証済み、GA4上の受信は本番有効化後に確認が必要。必要なら人間が`diagnostic_status`、`diagnostic_phase`、`purchase_purpose`をイベント範囲で登録する。既存のディメンションを削除しない。理由件数をGA4カスタム指標として登録する場合も人の判断とする。

施策前の同run基準値→承認・公開日時→公開後の同じ28日窓を比較する。operator/unknown、観測日、母数、商品データ更新日時、イベント新設日時を明記。全期間が揃い十分なサンプルになるまで自動の効果最適化をしない。GSCとGA4は別集計。クリックと楽天確定成果を区別し、楽天成果未接続のため売上改善は未確認。
